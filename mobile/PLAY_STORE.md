# Google Play 내부 테스트 등록

가계부는 초대받은 Google 계정만 쓰는 앱이라 **내부 테스트** 트랙으로 배포해요. 지정한 사람(최대 100명)만 Play 스토어에서 설치하고, 업데이트도 Play로 받아요. 심사가 거의 없고, 개인 개발자 계정의 "비공개 테스트 12명 · 14일" 조건도 없어요.

## 1. AAB 만들기

```bash
npm run build:aab
```

- 결과물: `dist/budget-book-v<번호>.aab`. EAS 키(업로드 키)로 서명되고, 모든 CPU용이 들어가요(Play가 기기별로 나눠 줘요).
- 올릴 때마다 번호가 하나씩 올라가요. Play는 같은 번호를 두 번 받지 않아요.

## 2. 앱 만들기 (Play Console, 한 번)

1. **앱 만들기**: 앱 이름 `잔잔한 가계부`, 기본 언어 `한국어`, 앱, 무료. 선언 항목 체크.
2. 패키지 이름은 첫 AAB를 올릴 때 `com.budgetbook.mobile`로 정해져요(바꿀 수 없어요).

## 3. 내부 테스트 버전 올리기

1. **테스트 및 출시 → 테스트 → 내부 테스트 → 테스터** 탭: 이메일 목록을 만들고 쓸 사람의 Google 계정을 넣어요. 같은 계정을 가계부의 **멤버**로도 초대해야 로그인돼요.
2. **새 버전 만들기**: Play 앱 서명은 기본값(Google이 관리) 그대로 두고 AAB를 올려요. 출시 노트 예: `첫 내부 테스트 버전`.
3. 저장 → 검토 → **내부 테스트로 출시**.
4. 테스터 탭의 **참여 링크(웹에서 참여)**를 테스터에게 보내요. 링크에서 수락한 뒤 Play 스토어에서 설치해요.

## 4. Google 로그인: Play 서명 키 등록 (꼭 해야 해요)

Play는 올린 AAB를 **Google의 앱 서명 키로 다시 서명**해서 배포해요. 그래서 Play에서 받은 앱은 SHA-1이 달라져서, 이걸 등록하지 않으면 Google 로그인이 실패해요.

1. Play Console **테스트 및 출시 → 앱 무결성 → 앱 서명**: "앱 서명 키 인증서"의 **SHA-1**을 복사해요.
2. Google Cloud Console → 사용자 인증 정보 → **OAuth 클라이언트 ID 만들기 → Android**: 패키지 `com.budgetbook.mobile`, 방금 복사한 SHA-1.

| 키 | SHA-1 | 쓰는 곳 |
|---|---|---|
| 업로드 키(EAS 키스토어) | `BA:E8:F1:A5:0D:B7:66:68:6D:69:4C:A6:2D:07:C5:20:DA:43:9D:5D` | 직접 설치한 APK |
| Play 앱 서명 키 | Play Console에서 확인 | Play에서 설치한 앱 |
| 디버그 키 | `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25` | 개발용 앱(`.dev`) |

> 직접 설치한 APK와 Play 버전은 서명이 달라서 서로 업데이트로 설치되지 않아요. Play 버전을 처음 설치할 때는 기존 `잔잔한 가계부`(개발용 아님)를 지우고 설치하세요. 데이터는 서버에 있어서 지워지지 않아요.

## 5. 앱 콘텐츠 (정책 → 앱 콘텐츠)

| 항목 | 답 |
|---|---|
| 개인정보처리방침 | `https://budget.woojin2.synology.me/privacy` (로그인 없이 열려요) |
| 앱 액세스 | 일부 기능 제한: 초대받은 Google 계정으로만 로그인. 심사용 계정이 필요하면 테스트용 Gmail을 멤버로 초대하고 그 계정을 적어요 |
| 광고 | 광고 없음 |
| 콘텐츠 등급 | 설문: 카테고리 "유틸리티, 생산성, 커뮤니케이션 등", 폭력·성적 내용·도박 등 모두 "아니요" |
| 타겟층 | 18세 이상 |
| 금융 기능 | 대출·결제·투자 등 금융 서비스를 제공하지 않음(개인 가계부 기록만) |
| 정부 앱 / 건강 앱 | 해당 없음 |

### 데이터 보안

- 데이터 수집: **예**. 전송 중 암호화: **예**. 삭제 요청 가능: **예**(가계부 소유자에게 요청).

| 데이터 유형 | 수집 | 공유 | 목적 | 필수 여부 |
|---|---|---|---|---|
| 개인 정보 → 이메일 주소 | 예 | 아니요 | 계정 관리, 앱 기능 | 필수 |
| 금융 정보 → 기타 금융 정보(직접 입력한 거래·잔액) | 예 | 아니요 | 앱 기능 | 필수 |
| 사진 및 동영상 → 사진 | 예(처리 후 저장 안 함) | 아니요(처리 업체 OpenRouter로 전송) | 앱 기능 | 선택 |
| 메시지 → 기타 인앱 메시지(결제 알림 문구) | 예(기기에만 저장, 규칙으로 못 읽은 문구만 분석 후 저장 안 함) | 아니요(처리 업체 OpenRouter로 전송) | 앱 기능 | 선택 |

결제 알림 대기함은 `NotificationListenerService`(알림 접근)를 써요. SMS 권한(READ_SMS 등)은 쓰지 않아서 권한 선언서는 필요 없어요. 다만 앱 콘텐츠의 데이터 보안 답변과 개인정보처리방침(`/privacy`)에 위 내용이 들어가 있어야 해요.

## 6. 스토어 등록정보 (내부 테스트도 필요)

- **앱 이름**: 잔잔한 가계부
- **간단한 설명**(80자 이내): `함께 쓰는 조용한 가계부. 거래·예산·저축을 한 곳에서 기록하고 보고서로 확인해요.`
- **자세한 설명**:

```
잔잔한 가계부는 가족이나 함께 사는 사람과 같이 쓰는 개인 가계부예요.

• 거래 기록: 지출·수입·이동을 빠르게 기록하고, 영수증 사진에서 거래를 불러올 수 있어요.
• 보고서: 월간·연간 수입과 지출, 고정비와 변동비, 분류별 지출을 한눈에 봐요.
• 잔고와 저축: 통장·카드별 잔고와 저축 계획, 월 저축 진행을 관리해요.
• 반복 항목: 월세·통신비처럼 매달 하는 거래를 한 번에 등록해요.
• 결제 알림 대기함: 카드 승인·출금 알림을 모아 두고, 확인한 것만 한 번에 등록해요.
• 함께 쓰기: 초대한 Google 계정끼리 같은 가계부를 보고 편집해요.

가계부 데이터는 소유자가 직접 운영하는 서버에 저장되며, 초대받은 계정만 로그인할 수 있어요.
```
